# T1-U4a/U4b verification cohort — Claude Fable 5.1

**Status:** Binding gate clarification. U4a and U4b remain separate implementation units with separate ownership and Fable review receipts; they are not independently commit-ready. The full-solution gate is required at the U4b cohort head.

**Review provenance:** Claude Fable 5.1, resumed T1-U4 session `8fc20ebe-d70e-47fe-8e1b-01d79e3bb527`, 2026-09-27. Read-only source and plan review; explicitly empty MCP configuration. This document records the public decision only.

## Reason for the cohort

U4a renames Core and Must TimeSpan APIs and code constants. Until U4b updates Guard, FluentValidation, and DataAnnotations callers, the solution still contains adapters calling the old Must names. The program-wide gate cannot honestly pass during this intermediate state. T-00 §9 makes its checks per-unit unless the unit specifies otherwise; T-01 U4a specifies Core/Must scoped acceptance, and U4b specifies adapter scopes. Therefore the scoped U4a checks are its contract, not an exception to quality gates. U4a cannot be committed or merged by itself because that would leave a non-compiling solution on the branch.

## U4a gate

After U4a, run only:

- Format Core and Must; Roslyn scan Core and Must with zero warnings.
- Core and Must tests.
- Isolated Core and Must coverage on `net8.0` and `net10.0`, each at 100% line and branch coverage.
- `audit nullability` and `audit must-codes`.

`audit must-codes` is executed at the U4a scoped gate as a recorded residue inventory: it passes
only if every Rule13 finding is one of the four old `GreaterThan`/`LessThan` clause and
`NotGreater`/`NotLess` code references in `src/PineGuard.DataAnnotations/StringTimeSpanAttributes.cs`
and `src/PineGuard.DataAnnotations/TimeSpanAttributes.cs`, any fifth or out-of-file finding blocks
U4a acceptance; the zero-finding requirement is deferred to the U4a/U4b cohort head, where the
command is rerun after U4b and must report zero with no baseline key, alias, exception or suppression
added. See the [MustCodes deferral ruling](../../../artifacts/reviews/t1-u4a-scoped-gates/fable-mustcodes-deferral.md).

Do not run the All-scope format, diagnostics, or test commands at U4a. The remaining adapter references to the old names are owned by U4b. Keep a read-only residue inventory using two exact sweeps, per Claude Fable 5.1's binding residue-count correction (2026-09-27).

`git grep` searches tracked files only, so `bin/` and `obj/` never appear. Sweep A and Sweep B answer different questions and are not expected to agree file-for-file: Sweep A is the ownership sweep — it lists everything U4b must clean. Sweep B is the stray sweep — it proves nothing outside U4b's ownership references the renamed identities. A Sweep A file with no Sweep B hit is normal.

**Sweep A, ownership sweep** (any old vocabulary inside U4b-owned TimeSpan files is residue, including stale comments such as `GuardStringTimeSpanClauses.cs:112`):

```text
git grep -n -E "GreaterThan|LessThan|NotGreater|NotLess|not-greater|not-less" -- 'src/PineGuard.GuardClauses/*TimeSpan*' 'src/PineGuard.FluentValidation/*TimeSpan*' 'src/PineGuard.DataAnnotations/*TimeSpan*' 'tests/PineGuard.GuardClauses.UnitTests/*TimeSpan*' 'tests/PineGuard.FluentValidation.UnitTests/*TimeSpan*' 'tests/PineGuard.DataAnnotations.UnitTests/*TimeSpan*'
```

**Sweep B, stray sweep** (TimeSpan-specific identities anywhere outside the plan folder):

```text
git grep -n -E "TimeSpanRules\.Is(GreaterThan|LessThan)\b|StringRules\.TimeSpan\.Is(GreaterThan|LessThan)\b|Duration\.(NotGreater|NotLess)\b|time\.duration\.not-(greater|less)\b|TimeSpanRulesFixtures\.Is(GreaterThan|LessThan)\b|TimeSpanIs(GreaterThan|LessThan)\b|(GreaterThan|LessThan)TimeSpan(String)?(Attribute)?\b" -- src tests apps docs ':!docs/ai/plans/**'
```

**U4b inventory (18 files, not 14).** The live U4b selectors (`*TimeSpan*` under the three adapter source projects and their three test projects) resolve today to exactly six adapter source files (`GuardTimeSpanClauses.cs`, `GuardStringTimeSpanClauses.cs`, `FluentTimeSpanExtensions.cs`, `FluentStringTimeSpanExtensions.cs`, `TimeSpanAttributes.cs`, `StringTimeSpanAttributes.cs`) and twelve adapter test files (`Guard{,String}TimeSpanClauses{Tests,TestData}.cs`, `Fluent{,String}TimeSpanExtensions{Tests,TestData}.cs`, `{,String}TimeSpanAttributes{Tests,TestData}.cs` under their respective `*.UnitTests` roots). Every earlier mention of "14" in this document and in Fable's prior ACCEPT is superseded by this 18-file inventory, generated by the U4b pathspecs, not hand-maintained.

**U4a handoff criterion.** Handoff passes when all of the following hold:

- Sweep A: every matched path is one of the 18 files above. Match count is informational; it is not itself a criterion.
- Sweep B, source and tests: every matched path under `src/` or `tests/` is one of the 18 files.
- Sweep B, baseline: `apps/cli/config/baseline.json` is permitted to match only the four keys named in [the baseline-key ruling](temporal-u4a-baseline-key-ruling-fable.md) — `rules-usage:StringRules.TimeSpan.IsGreaterThan`, `rules-usage:StringRules.TimeSpan.IsLessThan` (lines 658–659), and `test-structure:missing:tests/PineGuard.DataAnnotations.UnitTests/StringTimeSpanAttributesTests.cs:GreaterThanTimeSpanString` and `…:LessThanTimeSpanString` (lines 1315–1316) — which stay in place until the cohort head. Any fifth baseline match, or any other path under `apps/` or `docs/`, is a U4a scope defect. The baseline stays in Sweep B's scope (rather than being excluded) so the check that no fifth key exists is preserved; the four-key allowance above is the exception.

Intermediate states between handoff and cohort head may show any counts; only the final state is judged.

## U4b and cohort-head gate

U4b performs the Guard, FluentValidation, and DataAnnotations renames, and — per [the baseline-key ruling](temporal-u4a-baseline-key-ruling-fable.md) — the paired, net-count-unchanged move of the four `apps/cli/config/baseline.json` keys named above. After that move:

- Sweep A returns no lines.
- Sweep B returns no lines, including from `baseline.json`, because the four old keys have been replaced by their renamed pairs (`IsLongerThan`/`IsShorterThan`; `LongerThanTimeSpanString`/`ShorterThanTimeSpanString`, or whatever exact test names U4b lands) with net key count unchanged and each pair cited in the receipt.
- `All` compiler diagnostics is green, and is the authoritative detector for any typed `Must.Be.GreaterThan(TimeSpan…)` caller that a name regex cannot see; both sweeps plus that run together define "zero residue" for the cohort acceptance.

Numeric fixtures (`GuardNumberClausesTestData.cs`, `MustNumberClausesTestData.cs` and `NumberRulesTestData.cs`, which reference `NumberRulesFixtures.IsGreaterThan`/`IsLessThan` through the `F` alias) stay excluded permanently: Sweep A cannot see them because of its `*TimeSpan*` pathspecs, and Sweep B cannot see them because it matches only TimeSpan-qualified identities. Both properties are by design; no command change is needed for this.

At the U4b head, run the complete T-00 §9 gate: All format, All compiler diagnostics, and All tests; isolated coverage for every touched scope (`Core`, `MustClauses`, `GuardClauses`, `FluentValidation`, `DataAnnotations`) on both target frameworks; `audit --gate`, `audit must-codes`, and `audit nullability`. Keep `audit layer-parity` at the completed Phase 1 cohort as already stated by U4b. Fable reviews U4b and then accepts the combined U4a/U4b evidence and zero-residue result.

The handoff artifact separates three sections: "source residue" (Sweep A paths), "stray check" (Sweep B paths under `src/` and `tests/`), and "deferred baseline keys" (exactly the four lines above).

After the cohort head passes, create one conventional commit whose body identifies both U4a and U4b and, per the baseline-key ruling, lists every moved baseline-key pair and attaches `git diff --stat apps/cli/config/baseline.json` showing equal insertions and deletions. Record the same commit hash on both tracker rows. Keep their dispatches, ownership, and review receipts distinct.
