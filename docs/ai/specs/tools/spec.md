# PineGuard Tools Specification

This specification governs the structure, naming, and implementation of PowerShell scripts in the `tools/` directory.

For operational documentation (usage examples, parameters, tool index), see:

- `tools/README.md` (root index of all tool directories)
- Each `tools/<directory>/README.md` (per-tool usage and parameters)

## 1. Naming Conventions

We use a strict **Verb-Noun** standard, with specific semantic meanings for verbs in this specific project context.

### 1.1 Verbs

- **`Run-`**: Orchestrator scripts.
  - Can call multiple child scripts.
  - Can have switches to control flow (e.g., `-All`, `-Project Core`).
  - **Output**: Generally console output, or artifacts generated by child scripts.
  - **Example**: `Run-GenAll.ps1`, `Run-Clean.ps1`, `Run-SmokeTestGapAnalysis.ps1`.

- **`Test-`**: Audit and Verification scripts.
  - Performs checks, scans, or assertions.
  - **Output**: JSON/Text reports in `artifacts/audit/` or console pass/fail.
  - **Example**: `Test-SpecNaming.ps1`, `Test-CoverageAnalysis.ps1`.

- **`Gen-`**: Generator scripts.
  - Generates reports or output based on templates or data.
  - **Output**: Files in `artifacts/` (preview) or `src/` (when `-EnableUpdateTarget` is set).
  - **Example**: `Gen-CoverageReport.ps1`.

- **`Clean-`**: Maintenance scripts.
  - Deletes files/folders.
  - **Example**: `Clean-Artifacts.ps1`, `Clean-Root.ps1`.

- **`Find-`**: specialized Audit finders (sub-components).
  - Used by `Test-` scripts or `audit-cli` to locate specific items.
  - **Example**: `Find-UnusedMustGuard.ps1`.

### 1.2 Nouns

- Use PascalCase nouns.
- Be descriptive but concise.
- Avoid redundant project names if implied by folder.

## 2. Implementation Standards

### 2.1 File Structure

- **Root**: `tools/`
- **Orchestrators**: Placed at the root of their domain (e.g., `tools/code-coverage/Run-CodeCoverage.ps1`).
- **Helpers**: Use a dedicated `Import-*.ps1` / `Load-*.ps1` helper for shared logic (e.g., `tools/audit-cli/helpers/Load-AuditHelpers.ps1`). Avoid loose functions in orchestrators if reused.

### 2.2 Parameters

- Use `[CmdletBinding()]` to support common parameters (`-Verbose`, etc.).
- Use `[ValidateNotNullOrEmpty()]` for critical string paths.
- **Orchestrators**: Should support `-All` or functional-area switches (e.g., `-Core`, `-Must`) where applicable.
- **Generators**: MUST support `-EnableUpdateTarget` (boolean/switch) to control writing to `src/`. Default should be **safe** (preview only).

### 2.3 Output & Logging

- **Console**: Use `Write-Host` with colors for status:
  - Cyan: Activity start (`>>> Invoking ...`).
  - Green: Success (`Done.`, `Sequence Complete.`).
  - Yellow: Warnings/Skips.
  - Red: Errors (or throw).
- **Artifacts**: Write all reports to `artifacts/` root. Do not write to `src/` or `tools/` during execution (except code generators modifying source).

## 3. Dependency Management

- Scripts should resolve paths relative to `$PSScriptRoot`.
- Scripts should not assume strict CWD (should work from repo root or script dir), but documentation should recommend running from **repo root**.

### 2.4 PowerShell parse-safety (non-negotiable)

This repo relies on PowerShell tooling (audit + generators). Generated scripts MUST be syntactically stable and easy for linters/audits to parse.

Required file template/order:

1. Optional comment-based help block (`<# ... #>`) **exactly once**, at the very top.
2. `[CmdletBinding()]` immediately followed by a single `param(...)` block.
3. Script body.

Hard rules:

- Do not emit loose parameter declarations (or stray text) outside `param(...)`.
- Do not duplicate the comment-based help block (a common generator failure mode).
- Keep each script as a single, valid PowerShell file (no accidental concatenation of two scripts).
- Prefer splatting (`@args`) when forwarding parameters; avoid constructing command lines as strings.

Recommended defaults:

- `Set-StrictMode -Version Latest` for new scripts unless a script must remain lenient for compatibility.
- Resolve paths from `$PSScriptRoot` and accept `-RepoRoot` when operating on the repo.
